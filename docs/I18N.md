# Internationalization (i18n) Guide

IotaPlayer uses `i18next` and `react-i18next` in the renderer process alongside a lightweight, dependency-free localization module (`electron/i18n.ts`) in the Electron main process.

## Supported Languages

- **`en`** — English (default and fallback language)
- **`pl`** — Polish (`Polski`)
- **`system`** — Follows the operating system locale (`app.getLocale()`), falling back to `en` for unsupported locales.

## Architecture

### Renderer (`src/i18n/`)

- `src/i18n/config.ts` — Defines `SUPPORTED_LANGUAGES`, `DEFAULT_LANGUAGE` (`'en'`), `NAMESPACES`, and locale resolution helpers (`resolveSystemLocale`, `resolveAppLanguage`).
- `src/i18n/types.ts` — TypeScript module augmentation for `i18next` (`CustomTypeOptions`) giving compile-time key checking against the English resources.
- `src/i18n/index.ts` — Initializes `i18next` with `react-i18next` and exports `applyAppLanguage(language, systemLocale)`.
- `src/i18n/format.ts` — Locale-aware `Intl.NumberFormat`, `Intl.DateTimeFormat`, `Intl.RelativeTimeFormat`, and `Intl.DisplayNames` helpers.
- `src/i18n/lyricsSource.ts` — Maps lyrics source metadata to localized `player:lyricsSources.*` labels.
- `src/i18n/locales/<lang>/` — Namespaced JSON translation files:
  - `common.json` — Navigation, generic actions, fallbacks, loading states
  - `player.json` — Transport controls, queue/lyrics states, fullscreen UI, lyrics source labels
  - `library.json` — Artists, albums, tracks, search, favorites, recently played, pluralized counts
  - `playlists.json` — Playlist management, editor labels, empty states
  - `settings.json` — Settings categories, language selector, audio/lyrics/Discord/library/equalizer/speed labels

### Electron Main Process (`electron/i18n.ts`)

Main-process UI strings (native folder-picker dialog title, Discord Rich Presence status labels, and human-readable scan error formatting) live in `electron/i18n.ts` and read the persisted `language` setting from `electron/settings.ts` together with `app.getLocale()`.

### Non-Goals

User-owned music metadata (track titles, artist names, album titles), lyrics text, file extensions, and internal developer console logs are never translated.

## Adding a New Language

1. **Create locale JSON files**:
   Copy `src/i18n/locales/en/` to `src/i18n/locales/<code>/` and translate all five namespaces (`common.json`, `player.json`, `library.json`, `playlists.json`, `settings.json`), including any CLDR plural suffixes required by the target language (`_one`, `_few`, `_many`, `_other`, etc.).
2. **Register the locale in the renderer**:
   - Add the language code to `AppLanguage` and `normalizeAppLanguage` in `electron/settings.ts`, `electron/preload.ts`, and `src/types/electron.d.ts`.
   - Update `SUPPORTED_LANGUAGES`, `resolveSystemLocale`, and `resolveAppLanguage` in `src/i18n/config.ts`.
   - Import and register the new JSON resources in `src/i18n/index.ts`.
   - Add the language option to `settings.json` (`language.options.<code>`) and `src/views/SettingsView.tsx`.
3. **Register main-process strings**:
   - Add the locale to `ElectronLocale`, `resolveSystemLocale`, and `ELECTRON_STRINGS` in `electron/i18n.ts`.
4. **Validate**:
   Run:
   ```bash
   npx tsc -p tsconfig.app.json && npm run build && npm run lint && node --test tests/*.test.mjs
   ```
   `tests/i18n.test.mjs` automatically checks key parity, plural forms, placeholder consistency, locale resolution, and settings persistence.
